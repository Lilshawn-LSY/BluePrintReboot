# v1.5.8 Metadata Enrichment Frontend

Status: implementation, recorded local automated validation, and user-provided manual verification are complete. v1.5.8 PR-head CI, merge, tag, GitHub Release, post-merge `main` CI, and clean-PC restore remain separately NOT VERIFIED unless directly observed. See the generated [Current Release Status](../CURRENT_RELEASE_STATUS.md) for controlled evidence state.

v1.5.8 closes the existing Paper metadata-enrichment workflow in the web Reader. A user explicitly fetches a Paper-scoped, non-persistent candidate preview. The preview reuses supported PDF-derived DOI information, Crossref lookups, arXiv detection/lookup, and the repository's existing local fallback data where available; normal library scans and any automatic enrichment remain outside this flow.

Every editable metadata field shows its current saved value, candidate value, source/provenance, and an explicit state: unchanged, conflicting, candidate available, or unavailable. Missing provider values are unavailable rather than blank overwrite instructions. The user selects individual nonblank candidates and applies only those fields through the established revision-checked metadata command. Unselected/manual metadata is preserved exactly, and a successful apply remains visible after a deliberate reload.

Candidate retrieval and mutation are separate operations. Provider errors leave the Paper unchanged and may still return usable partial candidates with safe diagnostics. Stale revisions return the existing conflict response without retrying the write; the Reader retains the candidate selection and unrelated unsaved metadata/Reading Note drafts so the user can deliberately reload candidates and retry.

User-provided manual verification completed the preview non-mutation, current/candidate/provenance display, selective partial apply and reload, metadata/provider safety, unsaved Reading Note preservation, stale-conflict preservation, repeated-apply, and existing Reader/Project/Tag smoke scenarios. The canonical manifest and generated status retain the individual controlled evidence records.

Automatic/background or bulk enrichment, PDF directory import/scanning, full-text extraction, OCR, automatic overwrite, tag candidate generation or governance, citation export, backup/recovery redesign, and a Reader UX redesign are deferred to v1.5.9+.
