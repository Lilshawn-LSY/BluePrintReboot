# v1.5.5 Note Block Write and Project Links

Status: implementation and user-performed real-data runtime validation are complete; current counts and evidence boundaries are recorded in the generated [Current Release Status](../CURRENT_RELEASE_STATUS.md). Hosted CI, merge, tag, GitHub Release, and post-merge `main` CI remain separate and are not claimed here.

## Scope

v1.5.5 adds the bounded structured Note Block write slice to the web Reader while preserving the existing local JSON storage and Streamlit workflows. Users can read the current Paper's stored-order Note Block collection, explicitly create or edit allowlisted content, link a block to an existing writable Project, unlink it without deleting source data, and inspect typed Note Block summaries in Project Detail.

The existing block types (`summary`, `claim`, `method`, `evidence`, `question`, `idea`, and `limitation`) and content fields (`block_type`, `title`, `text`, `page`, `figure`, `quote`, and `tags`) remain canonical. Identity and timestamps remain server-owned.

## Command and concurrency boundaries

- `GET /papers/{paper_id}/note-blocks` returns the complete bounded normalized collection in stored order, its deterministic SHA-256 revision, source Paper identity, total, and safe current Project-link summaries.
- `POST /papers/{paper_id}/note-blocks` and `PATCH /papers/{paper_id}/note-blocks/{block_id}` are explicit, independent Note Block commands. There is no combined metadata/note/block save.
- `POST /projects/{project_id}/note-block-links` and `DELETE /projects/{project_id}/note-block-links/{link_id}` reuse the generic typed Project-link store and its allowlisted link types.
- Commands acquire the shared workspace lock, reload persistent state after lock acquisition, reject stale revisions before mutation, atomically replace only the owning file, reload and verify the exact result, and restore original bytes and timestamps after failure where possible.
- Exact no-op edits avoid a write. Exact duplicate Project/Note Block/link-type combinations return `unchanged`; distinct allowlisted link types remain separate links.

## Read and frontend behavior

- Project Detail resolves available Note Blocks to bounded typed summaries and distinguishes missing Note Block, missing source Paper, and unreadable Note Block storage without removing or repairing links.
- The Reader keeps Metadata, Reading Note, and Note Block drafts and command states independent. Note Block saves are explicit, conflicts and API failures preserve the draft, and Paper transitions remount the Paper-local workspace.
- Each Note Block offers a bounded existing-Project picker, an allowlisted link-type picker, duplicate-truthful add behavior, current links, and confirmed unlink. Archived Projects remain readable and expose no Project write controls.
- Project Detail separates Paper and Note Block links, supports stable Reader navigation with only Paper and block identities in the URL, and blocks link commands while a Project metadata draft is dirty.
- The same-origin bridge admits only exact allowlisted method/path pairs, requires JSON command bodies, rejects encoded path tricks and unlisted subpaths, and leaves PDF binary/Range behavior unchanged.

## Compatibility and privacy
