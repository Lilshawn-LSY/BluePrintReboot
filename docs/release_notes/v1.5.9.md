# v1.5.9 PDF Scan / Import Frontend

Status: implementation, local automated validation, and user-provided managed-PDF workflow verification are recorded separately from the remaining browser Network path-privacy check, PR-head CI, merge, tag, GitHub Release, post-merge CI, and clean-PC restore evidence. See the generated [Current Release Status](../CURRENT_RELEASE_STATUS.md) for the controlled record.

v1.5.9 closes the frontend workflow for PDFs that a user has already placed in BluePrintReboot's canonical managed `papers/` directory. It intentionally separates two operations:

1. **Scan PDFs** reads the recursive managed directory and an in-memory Paper-index snapshot, then previews only safe relative-path candidates. It does not create, update, repair, enrich, tag, or otherwise persist a Paper record.
2. **Import selected** accepts only selected safe managed-relative `.pdf` paths, revalidates each file under the shared workspace write lock, and registers only new files through the established scanner/index merge and atomic persistence path.

The Library presents new/importable, already-registered, invalid, and unavailable scan states. Invalid header, unavailable/read failure, disappeared-file, duplicate, and persistence outcomes are reported per selected PDF. One rejected candidate does not create a broken Paper or corrupt existing index rows, and successful selected candidates remain usable. Repeated scans/imports identify an already-registered file rather than creating another Paper record under the existing canonical path/stable-identity rules.

Imported records use the repository's existing filename-stem title fallback and initial schema defaults. They appear in the existing Paper collection, resolve through the existing Reader Snapshot and managed PDF API, and work with the v1.5.8 metadata-enrichment preview and selective apply workflow. Import does not invoke Crossref/arXiv/PDF metadata providers and does not add tags.

The release adds only two exact local API commands: `POST /papers/scan` and `POST /papers/import`. The same-origin bridge permits only those POST paths with JSON bodies. Neither command accepts an arbitrary filesystem path or exposes an absolute path to the browser.

Deferred: drag and drop, automatic watchers, OCR, full-text extraction, automatic enrichment/tags, semantic/content-hash deduplication redesign, moved-file repair, missing-file repair, orphan cleanup, bulk migration, backup redesign, citation workflow, and free-form folder management.
