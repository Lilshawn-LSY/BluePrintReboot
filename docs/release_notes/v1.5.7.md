# v1.5.7 Paper Tag Apply/Remove

Status: implementation is complete in the local feature branch. Automated repository validation is recorded only after it is run; browser, real-data, hosted CI, merge, tag, and publication evidence are not claimed here. See the generated [Current Release Status](../CURRENT_RELEASE_STATUS.md) for controlled evidence state.

v1.5.7 adds bounded Paper-local tag management to the web Reader. A user can view persisted Paper tags, explicitly add one normalized tag, or explicitly remove one tag. Tag commands use the stable `paper_id`, a tag-only deterministic revision, the shared workspace lock, reload-after-lock concurrency checks, atomic index persistence, post-write verification, and the existing rollback contract.

The commands preserve current compatibility: existing legacy or noncanonical Paper tags are retained, unrelated tags are not normalized away, exact duplicate adds and absent removes return truthful no-ops, and canonical/alias governance remains out of scope. A successful mutation refreshes the canonical Reading Note header while preserving the note body; the Reader refreshes a dirty draft header without discarding its unsaved body.

The API and same-origin bridge allow only exact tag command paths and JSON bodies. The Reader supplies canonical Tag Book values when available, preserves intended input on failures, exposes conflict reload, and reflects the canonical persisted tag set after success or reload. This release adds no Tag Book CRUD, alias changes, automatic or bulk tagging, database/cloud sync, or design-system overhaul.
