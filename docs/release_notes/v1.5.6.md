# v1.5.6 Project Workspace Closure

Status: implementation is complete. Current automated and manual evidence boundaries remain in the generated [Current Release Status](../CURRENT_RELEASE_STATUS.md); this note does not claim a browser, hosted-CI, merge, tag, or GitHub Release result that was not observed.

## Project workspace closure

`/projects` now reports distinct Paper and Note Block link counts. `/projects/{projectId}` keeps Project overview, explicit metadata/status/priority commands, linked Papers, and linked Note Blocks on one page. The two link collections remain visibly distinct, show bounded stored totals and orphan counts, and retain controlled available, missing, and unavailable target states without silently repairing or removing data.

Project Detail can now link an existing Note Block locally: choose a bounded existing Paper, load only that Paper's stored Note Blocks, choose an allowlisted Project link type, and explicitly add the link. The UI handles no available Papers, Papers with no Note Blocks, loading, unavailable and error states, retries, duplicate no-ops, stale link conflicts, and successful reloads. Failed commands retain the chosen Paper, Note Block, and link type where possible.

## Command and data-safety boundaries

The new Project-local picker reuses `GET /papers/{paper_id}/note-blocks` and `POST /projects/{project_id}/note-block-links`; it introduces no second persistence path or storage format. Project and link commands remain separate. A dirty Project metadata draft blocks link controls and is never silently discarded by a link reload.

The existing stable identities, local JSON stores, shared workspace locking, optimistic Project/link revisions, reload-after-lock checks, atomic replacement, verification, and rollback behavior remain in force. Archived Projects stay readable but expose no Project or link write controls. Direct Paper unlink now also rejects archived Projects at the command boundary.

## Regression coverage

Disposable tests cover Project metadata status/priority reload through list and detail reads; Paper and Note Block link add/remove reloads; Note Block links made through the canonical API path appearing in Project Detail; exact duplicate no-writes; stale revisions; archived write rejection; and retained orphan/unavailable target states. Frontend tests cover the bounded Project-local picker, canonical command use, independent dirty-draft protection, and typed count rendering.

## Deliberate exclusions

This release does not add drag and drop, PDF text selection or highlighting, Note Block delete/reorder, automatic Research Block generation, autosave, Tag changes, LLM tagging, graph UI, citation export, backup/repair changes, a design-system overhaul, Streamlit removal, an installer or desktop shell, a database, cloud sync, Project delete, or unarchive.
