# v1.6.1 — Draft preservation and unified save state

v1.6.1 adds automatic browser-local draft preservation around existing explicit,
revision-checked server writes. It does not add autosave, background sync, an
offline write queue, a merge editor, revision history, or a backend contract
redesign.

## Delivered

- Paper Notes retain local work through navigation, remount, refresh, API
  failure/unavailability/restart, and revision conflicts.
- The shared revision-aware draft primitive records the confirmed server value,
  current local draft, revision, latest remote value, generation, and one
  active request snapshot.
- A successful response only clears the exact sent snapshot. Newer in-flight
  edits remain local and unsaved.
- Conflicts preserve both the local draft and latest server value with explicit
  keep-my-draft, use-latest-server-value, and review paths.
- Reader metadata, per-Note-Block drafts, Project creation/metadata, and
  canonical Tag create/edit/alias forms use the same browser-local preservation
  approach.
- Save feedback uses Saved, Unsaved changes, Saving..., Save failed, Changed
  elsewhere, and Offline rather than raw revision/HTTP jargon.

## Validation scope

Focused frontend tests exercise draft persistence across reload/remount,
failure/offline recovery, conflict preservation, exact-snapshot completion,
in-flight edits, and duplicate-save exclusion. Full release validation and
manual browser recovery checks remain separately recorded in the generated
release status.
