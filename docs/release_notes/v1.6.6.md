# v1.6.6 — Task-first UX redesign

v1.6.6 is an experimental, production-quality redesign of the existing local
research workspace. It changes information hierarchy, action language,
contextual-surface behavior, and responsive composition without changing any
storage format, domain identity, API command meaning, or explicit-save timing.

## Research loop

The desktop workflow now makes the core loop visible: import or find a Paper,
decide what to read, read and record thoughts, connect Papers and Note Blocks
to Projects, then resume the relevant context later. Normal healthy system
state no longer competes with that work.

## Major surface changes

- **Dashboard** leads with a resume queue, locally preserved draft recovery,
  recent Projects, and direct task language such as Continue reading, Resume
  draft, Open Project, Reconnect PDF, and Review Diagnostics.
- **Library** remains a high-density catalogue. Its active-filter context,
  import/scan control, bounded local table scrolling, and selected-Paper
  inspector now separate finding, deciding, and acting. The inspector starts
  on its close control, closes with Escape, restores focus to the selected row,
  exposes its next action before maintenance, and scrolls independently.
- **Paper Detail** is a dossier: identity and PDF/reading state lead; abstract,
  canonical Tags, and Project context precede imported keywords and disclosed
  citation/metadata review.
- **Reader** retains the PDF as the primary visual stage and keeps Notes,
  Blocks, and Details in a named right-hand research panel. Reader utilities
  continue as focus-managed overlays and editor-specific SaveStatus remains
  beside only the editor it describes.
- **Projects** foreground research questions and linked material. Project
  collection rows show their working context, while Project Detail keeps
  Papers, Note Blocks, semantic relationships, and exceptional target states
  ahead of link maintenance and editing.
- **Tags** distinguishes generated candidates, canonical Tags, aliases, and
  imported Paper keywords. Lifecycle and advanced identity remain maintenance
  details rather than catalogue decoration.
- **Settings** remains a quiet local-workspace landing surface and hands verbose
  health, integrity, and backup detail to Diagnostics.

## Interaction and accessibility

- Shared contextual surfaces now define close, Escape, initial focus, focus
  return, and independent scrolling behavior.
- The global visible-focus treatment is a solid high-contrast outline with a
  separating ring. Inline text links use a consistent underline treatment;
  navigation and table-title links retain context-appropriate treatments.
- Essential small information uses contrast-safe secondary Ink or stronger;
  muted Ink is structural detail only. Icon controls retain labels and titles.
- Collection, inspector, drawer, and dossier layout rules cover wide desktop,
  compact desktop, narrow workspace, long identities, extensive tag sets, and
  exceptional PDF/extraction/draft states without adding fake product controls.

## Preserved behavior

The release leaves local-first storage, canonical `paper_id`, stable Paper and
Reader routes, managed-PDF containment/removal/archive safety, PDF.js rendering
and fit/zoom/position behavior, browser-local draft keys and recovery,
optimistic revisions, conflict recovery, explicit Save semantics, Note Block
identity/links, workspace locking, and read-only API boundaries unchanged.
