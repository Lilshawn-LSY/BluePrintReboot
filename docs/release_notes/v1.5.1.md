## Reader write vertical slice

v1.5.1 adds exactly two explicit local Reader commands:

- `PATCH /papers/{paper_id}/metadata` edits only `title`, `authors`, `year`, `journal`, `doi`, `abstract`, and `keywords`.
- `PUT /papers/{paper_id}/reading-note` saves the complete Reading Note after canonicalizing its header against current metadata.

The commands remain separate. There is no autosave, combined save endpoint, arbitrary-path proxy, database, cloud sync, background writer, or multi-user authentication.

## Consistency and concurrency

- Reader snapshots expose normalized editable metadata plus a deterministic SHA-256 metadata revision.
- Reading Note snapshots expose the SHA-256 of the exact UTF-8 content. An absent note uses the SHA-256 of zero bytes and an explicit `exists: false` marker.
- A standard-library OS lock serializes each local check-and-write critical section across FastAPI and Streamlit processes targeting the same index.
- Stale metadata revisions and note hashes return `409` before mutation.
- Metadata changes affecting `title`, `authors`, `year`, or `doi` refresh an existing canonical note header while preserving its section body.
- The metadata command snapshots the index and note and restores both if index persistence or note-header persistence cannot complete consistently.
- Note replacement remains an atomic UTF-8 write. Failed saves leave the submitted browser draft in memory and preserve the prior persisted file.

## Web Reader

- Metadata and Reading Note editors have independent Clean, Dirty, Saving, Saved, Conflict, and Error states.
- Each editor has its own Save and explicit conflict-reload action.
- Dirty drafts survive command errors and conflicts. Replacing a dirty version requires an explicit user action.
- Metadata header refresh retains a dirty Reading Note body and advances its persisted SHA-256 baseline.
- PDF.js document lifecycle and managed-PDF Range behavior remain independent from both save flows.

## Compatibility

The v1.5.0 Reader Snapshot GET route, managed PDF API, repository-local PDF.js worker, native fallback, stable `paper_id`, local-only API binding, and Streamlit workflows remain in place. Streamlit and the web Reader use the same index and Reading Note storage primitives.
