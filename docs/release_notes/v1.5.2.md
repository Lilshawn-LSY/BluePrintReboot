## Projects and Tags read parity

v1.5.2 replaces the Projects and Tags frontend placeholders with real local read-only contracts:

- `GET /projects` returns an allowlisted deterministic page with `total`, `limit`, `offset`, and `has_more`.
- `GET /projects/{project_id}` returns one stored Project plus a bounded page of real links and allowlisted linked-paper summaries.
- `GET /tags` returns an allowlisted deterministic page of canonical Tag Book records.
- `GET /tags/summary` returns fixed counts derived from existing paper-index/service evidence or an explicit unavailable state.

Unknown Projects return 404. Invalid pagination returns 422. Corrupt, unreadable, or contract-invalid local Project/Tag read models return a generic 503 without exception text, local paths, environment values, raw records, or private content.

## Read-only and privacy boundaries

Project and Tag routes call dedicated read-model services and API adapters rather than serializing storage dictionaries. They expose no absolute/local paths, storage locations, `source_paths`, raw Tag Book records, arbitrary paper-index fields, or link notes. Missing linked papers remain successful Project detail reads with an explicit `orphaned` state and no fabricated metadata.

The candidate summary aggregates only real deterministic suggestion output from existing paper-index records. If the index source is absent or unreadable, the response reports `availability: "unavailable"` and zero counts rather than generating candidates.

GET requests do not save, migrate, normalize, repair, rewrite, or create Projects, links, Tags, paper-index records, notes, or configuration. Disposable regression tests compare Project/Tag file bytes and modification times before and after browsing.

## Frontend

`/projects`, `/projects/{project_id}`, and `/tags` reuse the existing application shell, headers, sections, panels, tables, badges, typography, and responsive layout. The views distinguish loading, empty, API-offline, corrupt/read-model failure, retry, and Project not-found states. Orphaned paper links and unavailable candidate evidence are explicit.

The same-origin bridge allowlists only the exact new GET paths. It uses a safe response header to distinguish an unreachable API from an upstream read-model 503 without exposing upstream details. No Project or Tag create, edit, archive, delete, link, unlink, apply, remove, approval, rejection, merge, or governance control is present.
