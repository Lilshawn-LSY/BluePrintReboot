## Summary

## Command contracts

- `POST /projects` creates a server-identified Project.
- `PATCH /projects/{project_id}` updates only name, description, status, priority, and tags.
- `POST /projects/{project_id}/archive` performs a one-way archive and preserves links.
- `POST /projects/{project_id}/paper-links` links an existing Paper with an allowed link type.
- `DELETE /projects/{project_id}/paper-links/{link_id}` removes only that exact Paper link and never deletes the Paper.

Requests and responses use strict bounded schemas. Unknown and immutable fields are rejected. Project deletion, unarchive, Note Block targets, link notes, Tag writes, and Settings writes are absent. Controlled 404, 409, 422, and 503 responses do not expose local paths, submitted values, raw exceptions, or storage dictionaries.

## Revision, locking, and rollback

Project metadata commands use `project_revision`. Paper-link commands use `links_revision`, calculated over the complete stored link collection for the Project, including link types outside this command slice so concurrent state is not overwritten.

Every command acquires the shared workspace write lock, reloads the relevant stores, checks the expected revision, and performs an atomic replacement only in its owning store. Persisted state is reloaded and verified. If serialization, replacement, or post-write verification fails, the service restores the exact original bytes and timestamps, or removes a newly created file.

Exact no-op metadata updates and duplicate Paper links do not write. Stale commands and lock contention do not mutate state.

## Frontend

The Projects list contains an explicit bounded create form. Active Project detail contains explicit edit/save/cancel/archive actions and a real bounded picker of existing Papers. Archive and unlink require clear confirmation. Exact duplicate links report unchanged rather than fabricated success.

Conflicts and offline failures preserve the current Project draft or Paper selection and offer explicit reload/retry behavior. Metadata drafts must be saved or cancelled before link changes. Archived Project metadata and links remain readable while edit, archive, add-link, and unlink controls are absent.
