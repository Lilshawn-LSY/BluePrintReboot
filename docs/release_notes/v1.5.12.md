# v1.5.12 R-145 Pre-UX PDF Foundation

v1.5.12 closes the PDF rendering, selectable-text, selection-coordinate, and extraction/cache foundation before the separately scoped v1.6 Reader visual redesign. It preserves the v1.5.11 Library to Paper Detail to Reader workflow and does not add Research Block capture or persistence.

Canonical mutable validation and publication state is recorded in [Current Release Status](../CURRENT_RELEASE_STATUS.md).

## Included

- PDF.js canvas backing buffers use `clamp(devicePixelRatio × 1.5, 1, 3)` while CSS viewport dimensions, semantic Reader zoom, text-layer geometry, and selection coordinates remain unchanged.
- PDF.js text layers share the canvas page viewport, rotation, zoom, cancellation, retry, fallback, document-change, and unmount lifecycle.
- The internal selection contract uses canonical 1-based BluePrint page numbers and top-left rectangles normalized to the rotated logical page viewport.
- Default `pdf-inspector==0.2.6` is the preferred provider and is isolated behind BluePrint-owned structured document/page/position models. Its 0-based page-Markdown fields and 1-based OCR/position fields are normalized at the adapter boundary; MarkItDown remains an optional fallback.
- Structured extraction records text/scanned/image-based/mixed classification, confidence, page count, per-page text/Markdown/positioned items, OCR-needed pages/reasons, warnings/errors, provider identity/version, and the canonical cache source revision.
- One deterministic page-ordered Markdown/plain-text projection feeds the existing extracted-text cache, `PdfProfileExtraction`, and `PaperTextProfile`; MarkItDown then pypdf remain compatibility fallbacks.
- `GET /papers/{paper_id}/full-text/status`, `GET /papers/{paper_id}/full-text`, and explicit `POST /papers/{paper_id}/full-text/extract` expose the backend-owned workflow to a compact Reader Full Text section.
- Metadata enrichment preview consumes one request-scoped local evidence result: the current canonical cache when reusable, otherwise a bounded non-persisting `pdf-inspector` -> MarkItDown -> pypdf pass. DOI/arXiv detection, PDF-profile parsing, and title fallback share it without creating or replacing extraction state.
- Cache metadata adds explicit extraction/cache state, structured output, and reusable OCR-needed results while retaining SHA-256 stale detection and prior-valid-cache preservation.
- MarkItDown and pypdf remain compatibility fallbacks when `pdf-inspector` is unavailable, fails, or produces no locally usable text.

## Excluded

No OCR engine, semantic/full-text search, background extraction, automatic import extraction/scheduling, synchronized scrolling, selection/highlight persistence, Note Block or Research Block creation, drag/drop, Reader visual redesign, installer, database migration, or `paper_id` change is included.

## Evidence

- Focused and full local automated results are recorded only in the canonical release manifest after they run.
- User-reported normal-PDF rendering, zoom, text selection/drag, lifecycle behavior, and improved visual quality are recorded without extending that evidence to the new supersampling or Full Text surface.
- Supersampling-specific DPR, frontend Full Text, biology/multi-column extraction, scanned/mixed OCR-needed, cache/restart, and stale-source checks remain **NOT VERIFIED** until user-performed.
- GitHub Actions, PR, merge, tag, GitHub Release, post-merge validation, and clean-PC restore are **NOT VERIFIED** unless separately observed.
