# v1.5.11 Library / Paper Workflow Closure

Status: implementation, local automated validation, and user-provided manual browser/runtime validation are recorded separately from hosted CI, merge, tag, and publication evidence. See the generated [Current Release Status](../CURRENT_RELEASE_STATUS.md).

v1.5.11 closes the bounded Library/Paper workflow before the v1.6 UX redesign. Library is the primary web collection surface; stable Paper Detail and Reader resource URLs remain `/papers/{paper_id}` and `/papers/{paper_id}/reader`.

## Coherent collection workflow

Library now combines managed-PDF scan/import, the registered Paper collection, bounded server-side search, exact tag/year/reading-status filters, pagination, Paper Detail/Reader navigation, and explicit metadata enrichment preview/selective apply. Search is case-insensitive over normalized title, authors, journal, DOI, tags, and keywords, applies before pagination, and remains lifecycle-aware. No filesystem paths or full-text content are exposed to the browser.

The legacy `/papers` collection URL is retained as a Library signpost, but Papers is no longer a primary sidebar destination. Paper Detail returns to Library; Reader keeps its existing dirty-draft safeguards and provides both Paper Detail and Library paths.

User-provided manual validation on 2026-08-16 covered Library as the primary Paper workflow, the legacy `/papers` signpost, stable Paper Detail and Reader navigation, server-side search/filter/pagination, existing Paper browsing and missing-PDF state, scan/import without automatic enrichment or tagging, enrichment preview/selective apply, exact SHA-256 duplicate detection, reconnect preservation, ambiguous non-mutating repair, offline/failure/conflict behavior, browser Network privacy, existing Reader/Project/Tag/Note Block/Settings regressions, and restart persistence.

## Exact-content reconnect

The managed scan distinguishes a registered path, exact duplicate content at another managed path, a uniquely reconnectable missing Paper, and ambiguous exact matches. Reconnect is an explicit command limited to the managed papers directory. It re-evaluates the candidate under the workspace write lock, requires one missing indexed Paper and one exact SHA-256 identity, then atomically updates only that Paper row's managed file identity fields.

Reconnect never creates or merges a Paper. The stable `paper_id`, metadata, Reading Note, Note Blocks, Project links, and tags remain attached to the existing Paper. Stale, missing, unavailable, or ambiguous candidates reject without mutation.

## Deliberately deferred

This release does not add a visual redesign, PDF renderer changes, text selection, OCR, semantic/full-text search, watcher/background import, drag-and-drop, automatic/bulk enrichment, automatic tags, LLM features, citation export, backup/recovery redesign, or destructive bulk maintenance.
