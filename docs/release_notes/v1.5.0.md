# v1.5.0-reader-snapshot-readonly-vertical-slice

v1.5.0 is a product vertical slice: the browser Reader can now show the managed PDF and the last explicitly saved Reading Note together through one coherent read-only snapshot. The immutable released baseline remains v1.4.0; this runtime target does not claim a v1.5.0 tag, GitHub Release, pull request, merge, hosted workflow, or post-merge result.

Current mutable evidence is rendered from the canonical schema 4.0 manifest in [Current Release Status](../CURRENT_RELEASE_STATUS.md).

## API contract

- Added strict `ReaderNoteHeader`, `ReaderNoteBaseline`, and `ReaderSnapshotResponse` schemas.
- Added `adapt_reader_snapshot()`, reusing the established paper-detail adapter and exposing only allowlisted header/baseline fields.
- Preserved `saved_note_content` exactly; the adapter neither rereads the note nor recomputes its hash.
- Added `GET /papers/{paper_id}/reader`, backed only by `build_reader_snapshot(paper_id)`.
- Unknown papers return generic 404; builder/contract failures return generic 503. Missing PDF, absent note, and recoverable unreadable-note warning remain HTTP 200 snapshot states.

## Web Reader

- Added matching TypeScript snapshot types and `getReaderSnapshot(paperId)`.
- Allowlisted exactly `papers/{paper_id}/reader` in the same-origin GET bridge. Reader JSON does not receive PDF Range forwarding.
- Switched ReaderView from a separate paper-detail request to one snapshot request.
- Added an accessible companion panel that renders persisted note text in a selectable, independently scrolling, pre-wrapped plain-text surface.
- Kept missing note, unreadable note, missing PDF, not found, API unavailable/retry, and paper transition states distinct.

## Safety and compatibility

- No POST, PUT, PATCH, or DELETE route was added.
- No note editor, save/apply control, autosave, metadata mutation, storage migration, database, dependency, OCR, cloud sync, or project/tag API was added.
- The PDF.js controller, worker lifecycle, native fallback, managed-root containment, byte Range API, stable `paper_id`, and Streamlit state/write workflows are unchanged.
- Automated fixtures use only synthetic identities, note text, and workspace-relative paths.

## Browser PDF.js compatibility

- Before the compatibility change, the native browser fallback displayed the same managed PDF successfully.
- The managed PDF API and same-origin bridge returned valid HTTP 206 responses, `application/pdf`, correct `Content-Range`/`Accept-Ranges`, `%PDF` starting bytes, and the same file size.
- After switching the PDF.js main module and worker URL to the `pdfjs-dist` legacy build, the real browser PDF.js path rendered the first page successfully.
- Reader diagnostics reported Document loads 1, Page renders 1, and Render cancellations 0.

## Validation boundary

Focused Reader Snapshot API, managed-PDF API, release/version contracts, canonical smoke, the full Python suite, frontend lint, production build, bridge/rendered-source tests, and PDF.js controller regressions pass locally. The canonical manifest records the current counts; they are evidence, not validator invariants.

Browser PDF delivery and first-page rendering are verified. Persisted-note pairing, note absence/read failure, missing PDF, paper transition, and API restart remain separate open runtime checks.
