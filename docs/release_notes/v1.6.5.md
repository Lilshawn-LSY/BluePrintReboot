# v1.6.5 — Visual language & design system refinement

v1.6.5 completes the final local desktop workflow and presentation pass. It
keeps explicit Save, browser-local drafts, revision/conflict safeguards, and
managed-PDF safety intact. No migration is required and no persistent storage
format changes.

## Visual system

- Locks the shared White / Ink / Blueprint Blue palette: cool white canvas and
  working surfaces, restrained ink typography, explicit faint/default/strong
  rules, and Blueprint Blue only for interaction, focus, links, selection, and
  active workspace controls.
- Tunes Blueprint Blue to the brighter 700/600/500/300/100/050 scale while
  retaining White + Ink as the dominant surface treatment.
- Establishes shared faint, default, and strong rule tokens so hierarchy comes
  from structure rather than repeated card borders and shadows.
- Tightens working-surface geometry, keeps ordinary panels flat, and reserves
  shadows for genuine overlays such as drawers, menus, and dialogs.
- Adds local/system typography roles for UI Sans, limited Research Serif note
  previews, and Technical Mono identifiers without remote font loading.
- Replaces the placeholder sidebar `B` with an accessible inline-vector
  Constructed B brand mark.
- Reworks `StatusBadge` presentation into quiet inline labels for ordinary
  metadata, compact chips for taxonomy, and stronger badges for exceptional
  states such as Missing PDF, Failed, Offline, Conflict, and Archived.
- Gives compact domain status markers restrained semantic tones without
  returning to colorful pills: Reading/active use Blueprint Blue, completed
  states use muted green, paused/high use muted amber, archive/low/normal use
  slate, and urgent/critical use the existing danger red.
- Distinguishes canonical tags (compact Blueprint Blue left-rule notation),
  neutral aliases/imported keywords, and quieter generated candidates, removing
  the remaining stretched pill-tag language.
- Keeps selection and hover restrained through subtle surface changes, inset
  accent rules, border changes, and short functional transitions.

## Page archetypes

- Dashboard is a flat workbench with direct continuation rows rather than a
  collection of metric cards.
- Library, Projects, and Tags use catalogue/index tables with stronger table
  rules, quieter state labels, and taxonomy chips only where they improve
  scanning.
- Library gives title the flexible table column and constrains the remaining
  columns; its selected-paper inspector stays side-by-side at wide desktop
  widths and becomes a bounded right overlay at 1280–1439px, preventing
  body-level horizontal overflow.
- Project Detail reads as a dossier: compact metadata, indexed linked material,
  and working forms retain boundaries only where the interaction needs one.
- Reader preserves its existing behavior while reducing chrome depth: compact
  controls, Blueprint Blue active underlines/borders, stronger workspace
  separators, a focused resize boundary, and overlay-only depth. PDF pages
  remain the deliberate exception because they are physical document surfaces.
- Settings is a quiet utility surface rather than a prominent card cluster.

## Final workflow polish

- Reader reserves a structural navigation slot, so `Library` remains visible
  beside the fixed overlay trigger while long Paper titles truncate safely.
- Project-linked Papers and Note Blocks use restrained semantic relationship
  labels instead of Blueprint-Blue or pill-style status treatment.
- Tags registry removes the prominent deprecated badge; lifecycle is retained
  in the Manage/advanced context only.
- Library scan/import/upload feedback is compact and detailed results live in
  a bounded drawer. Library now supports multiple PDF picker and drag/drop
  imports through the managed duplicate-safe import path.
- Metadata enrichment stays selected-Paper-specific in the bounded inspector,
  with current-vs-candidate review and selective explicit application.
- Reading status (`Unread`, `Reading`, `Read`, and legacy `Finished`) is
  editable from Library and Reader through one revision-checked metadata
  command bound explicitly to the same canonical index and note roots as the
  Library and Reader read models.
- `Remove PDF file` creates a verified recovery copy before removing only
  managed bytes; `Remove Paper from Library` archives rather than destroys
  metadata, PDFs, notes, blocks, tags, or Project links. Full deletion remains
  deliberately unavailable.
- New Reader Note Blocks persist and display newest-first by `created_at`, then
  retain focus in the edit workflow without changing block IDs, links, drafts,
  or conflicts. Editing an older Block does not promote it.

## Safety and validation scope

Reader PDF rendering/fit/zoom, routes, browser-local drafts, explicit Save,
and conflict safeguards remain unchanged. Manual visual verification at the
supported desktop widths remains outstanding and is not claimed here; see the generated
