# v1.6.3 — Reader interaction & UX polish

v1.6.3 is a focused desktop research-workflow polish release. It keeps the
v1.6.2 information architecture and adds no storage migration, background tag
work, or automatic saving.

## Reader interaction changes

- Reader keeps compact Paper context and separates persistent work into Note,
  Blocks, and Details tabs. Tab changes retain Paper Note, metadata, Note
  Blocks, previews, drafts, and conflict state.
- The desktop context panel is session-resizable from 320px to 520px with a
  keyboard-accessible range control and reset action.
- Tags and Full Text open as a focus-managed overlay drawer. They no longer
  reduce PDF stage width or disturb reading position; Escape and Close return
  focus to the opener.
- PDF.js adds fit width, fit page, and manual zoom modes. Fit calculations use
  available stage dimensions while preserving high-DPI canvas and selectable
  text alignment.
- Normal Reader and Project navigation no longer blocks on drafts already
  preserved locally. Restored work shows a compact status, while explicit Save
  remains the only authoritative server write.

## Collection and workflow improvements

- Library search debounces, known tags use a searchable canonical-tag list,
  reading state is structured, and Paper titles navigate normally to Paper
  Detail. Inspect is a separate keyboard-operable action.
- The Library inspector shares Paper Detail's display-only abstract
  normalization and collapses long abstracts with Show more / Show less.
- Dashboard emphasizes Continue reading, active projects, compact recent
  activity, locally available draft context, and Diagnostics-backed attention
  only when action is needed.
- Projects adds search, status/priority filters, and recently-updated, name,
  and priority ordering while retaining pagination and existing create,
  archive, link, draft, and conflict behavior.

## Minimal Tags candidate read-model extension

- `GET /tags/review-queue` provides a bounded read-only list of Papers with
  already-persisted reviewable candidates, including safe title, counts,
  progress, and a short label preview.
- Review opens the corresponding Reader Tags utility. The queue never
  generates candidates, applies tags, or exposes raw identifiers in normal
  task surfaces.

## Visual, copy, and safety guarantees

- Product copy favors saved-version and task language; technical Tag identity
  is restricted to advanced details.
- Tabs, drawers, icon controls, inspectors, and link editing preserve visible
  focus, keyboard access, labels, live status, Escape behavior, and focus
  restoration.
- Local-first storage, managed PDF identity/path rules, explicit server Save,
  browser-local drafts, revision/conflict safeguards, archive behavior, and
  existing routes remain unchanged.

## Validation scope

Focused backend and frontend coverage exercises queue non-mutation and API
boundaries, Reader tab/panel/drawer/fit behavior, draft preservation,
